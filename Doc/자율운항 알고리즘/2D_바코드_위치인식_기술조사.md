# 카메라 기반 2D 바코드 위치 인식 기술 조사

> 수상 드론 자율 주행 적용 관점 | 작성일: 2026-05-06

---

## 1. 개요

2D 바코드를 랜드마크로 활용하여 카메라로 드론/로봇의 절대 위치를 추정하는 기법.  
GPS 음영 지역이나 정밀 위치 요구 환경(도킹, 수거 작업 등)에서 보조 또는 주 측위 수단으로 사용된다.

**수상 드론 적용 시나리오:**
- 수거 스테이션 귀환 시 정밀 도킹
- 수면 위 부유물 위치 마킹 (고정 부표에 마커 부착)
- GPS 오차 보정을 위한 절대 위치 보정점 (Waypoint Anchor)

## 2. 주요 2D 마커 종류 비교

| 마커 종류 | 해상도 요건 | 검출 거리 | 6-DoF 추정 | 특징 |
|-----------|------------|----------|-----------|------|
| **QR Code** | 낮음 | 중거리 | △ (별도 처리 필요) | 데이터 인코딩 가능, 범용성 최고 |
| **ArUco** | 낮음 | 중~장거리 | ✓ | OpenCV 내장, 경량, 드론 업계 표준 |
| **AprilTag** | 낮음 | 장거리 | ✓ | ArUco보다 검출률 우수, CPU 부하 낮음 |
| **STag** | 중간 | 중거리 | ✓ | 회전 불변, 조명 변화에 강함 |
| **ChArUco** | 중간 | 단~중거리 | ✓✓ | 카메라 캘리브레이션 + 포즈 추정 동시 |
| **Whycode** | 낮음 | 장거리 | ✓ | 수중/수면 환경 연구 사례 있음 |

### 권장: **AprilTag v3** 또는 **ArUco**

```
이유:
- ROS2 생태계 완전 지원
- BlueRobotics 수상 드론 + Companion Computer(RPi/Jetson) 조합에서 검증됨
- 6-DoF pose estimation → 드론 자세 보정까지 가능
```

## 3. 작동 원리: 카메라-마커 포즈 추정

### 3.1 PnP(Perspective-n-Point) 알고리즘

마커의 4개 코너(월드 좌표) ↔ 이미지 투영(픽셀 좌표) 대응으로 카메라 위치 역산.

```
[Rotation | Translation] = solvePnP(objectPoints, imagePoints, K, distCoeffs)
```

- `K`: 카메라 내부 파라미터 행렬 (fx, fy, cx, cy)
- `distCoeffs`: 렌즈 왜곡 계수
- 출력: 마커 기준 카메라의 (R, T) → 위치 (x, y, z) + 자세 (roll, pitch, yaw)

### 3.2 위치 정밀도 영향 인자

```
정밀도 ∝ (마커 크기 × 해상도) / 거리²

예시: 20cm 마커, 1m 거리 → 위치 오차 ~1-3mm
      20cm 마커, 5m 거리 → 위치 오차 ~2-5cm
```

## 4. 구현 스택 (현재 트렌드)

### 4.1 OpenCV + ArUco (C++)

```cpp
#include <opencv2/aruco.hpp>

// 마커 검출
std::vector<int> ids;
std::vector<std::vector<cv::Point2f>> corners;
cv::aruco::detectMarkers(frame, dictionary, corners, ids);

// 포즈 추정 (각 마커별 rvec, tvec)
std::vector<cv::Vec3d> rvecs, tvecs;
cv::aruco::estimatePoseSingleMarkers(
    corners, markerLength, cameraMatrix, distCoeffs, rvecs, tvecs);

// tvec = [x, y, z] in meter (마커 기준 카메라 위치)
```

**메모리:** 단일 프레임 처리 시 ~2-5MB (640×480 기준)  
**성능:** RPi4에서 30fps 640×480 가능

### 4.2 AprilTag (C/Java/Python)

```c
// C API
apriltag_detector_t *td = apriltag_detector_create();
apriltag_family_t *tf = tag36h11_create();
apriltag_detector_add_family(td, tf);

zarray_t *detections = apriltag_detector_detect(td, im);
for (int i = 0; i < zarray_size(detections); i++) {
    apriltag_detection_t *det;
    zarray_get(detections, i, &det);
    // det->p[0..3]: 코너 좌표
    // pose estimation은 apriltag_pose.h 사용
}
```

**트레이드오프:**
- AprilTag3: ArUco 대비 검출률 +15~20%, CPU 사용량 -20%
- 단, 라이브러리 크기 약 2배

### 4.3 ROS2 통합 (Humble/Iron/Jazzy)

```yaml
# apriltag_ros 패키지 설정
tag_family: 'tag36h11'
tag_threads: 2
tag_decimate: 1.0        # 해상도 다운샘플 배율 (속도 ↔ 정밀도)
tag_blur: 0.0
tag_refine_edges: 1
tag_debug: 0

standalone_tags:
  - {id: 0, size: 0.20}  # ID 0번, 20cm 마커
  - {id: 1, size: 0.20}
```

**토픽 출력:**
- `/apriltag/detections` → `apriltag_msgs/AprilTagDetectionArray`
- `/tf` → 마커→카메라 변환 자동 발행

## 5. 수상 드론 특화 고려사항

### 5.1 수면 반사 노이즈 대응

수면 반사는 마커 검출의 최대 적.

```
대응 전략:
1. 편광 필터 (Circular Polarizer) 카메라 렌즈 장착
2. 마커를 수면보다 높은 위치(부표 상단, 기둥 등)에 부착
3. 적외선 차단 필터 + 고대비 마커 (흑백 대비 극대화)
4. 조명 적응형 이진화: CLAHE 전처리 적용
```

```cpp
// CLAHE 전처리로 조명 불균일 보정
cv::Ptr<cv::CLAHE> clahe = cv::createCLAHE(2.0, cv::Size(8, 8));
clahe->apply(grayFrame, enhancedFrame);
// 이후 ArUco/AprilTag 검출
```

### 5.2 드론 진동 및 모션 블러

```
- 셔터 속도: 1/500s 이상 권장 (수면 파도 진동 ~2-5Hz)
- 전자식 이미지 안정화(EIS) 또는 짐벌 사용
- 고해상도보다 고프레임레이트 우선 (60fps, 720p > 30fps, 1080p)
```

### 5.3 다중 마커 맵 기반 위치 추정

단일 마커 의존 → 마커 가려짐 시 위치 소실 문제.

```
해결책: ArUco Map / Multi-tag Localization
- 여러 마커를 사전에 측량한 맵으로 등록
- 하나 이상 검출 시 weighted least-squares로 위치 퓨전
- 라이브러리: aruco_mapping (ROS), IPPE (OpenCV)
```

## 6. 센서 퓨전 아키텍처 (라이더/초음파 + 마커)

```
┌─────────────┐    ┌──────────────┐    ┌─────────────────┐
│  LiDAR      │───▶│              │    │                 │
│  (장애물)    │    │   EKF/UKF   │───▶│  최종 위치 추정  │
├─────────────┤    │  센서 퓨전   │    │  (x, y, yaw)   │
│  초음파      │───▶│              │    │                 │
│  (근거리)    │    └──────────────┘    └─────────────────┘
├─────────────┤           ▲
│  카메라      │           │
│  +마커 PnP  │───────────┘
│  (절대위치)  │  (GPS 없을 때 절대 위치 보정)
└─────────────┘
```

**퓨전 전략:**
- GPS 신호 정상: GPS + IMU (마커는 보정 보조)
- GPS 음영: 마커 PnP + IMU dead reckoning
- 도킹 진입 3m 이내: 마커 PnP 단독 (최고 정밀도 모드)

## 7. 최신 트렌드 (2024-2025)

### 7.1 딥러닝 기반 마커 검출

기존 이진화 파이프라인의 한계(극단적 조명, 수면 왜곡) 극복.

- **DeepTag (2022~)**: CNN으로 마커 코너 검출 → ArUco 대비 악조건 검출률 2-3배
- **Neural AprilTag**: 엣지 검출 단계를 뉴럴넷으로 대체
- **Jetson Orin** 기준: DeepTag 실시간 처리 가능 (~15ms/frame)

### 7.2 이벤트 카메라 + 마커

- 이벤트 카메라(DVS)는 모션 블러 없음, HDR 120dB
- 수면 반사·드론 고속 이동에 이론적으로 유리
- 아직 드론 상용화 초기 단계 (2024년 연구 활발)

### 7.3 마커리스 비주얼 오도메트리와의 병행

```
ORB-SLAM3 / RTAB-Map (마커리스) + 마커 (절대 위치 앵커)
→ 마커 없는 구간: VO로 상대 위치 추적
→ 마커 검출 시: 절대 위치로 드리프트 보정
```

## 9. 구현 로드맵

```
Phase 1: 기초 설정 (1-2주)
  ├─ 카메라 캘리브레이션 (체커보드)
  ├─ ArUco 단일 마커 포즈 추정 검증
  └─ ROS2 apriltag_ros 노드 통합

Phase 2: 환경 적응 (2-3주)
  ├─ 수면 환경 테스트 (실외 수조)
  ├─ CLAHE 전처리 튜닝
  └─ 조명 조건별 검출률 측정

Phase 3: 센서 퓨전 (3-4주)
  ├─ EKF로 마커 + IMU 퓨전
  ├─ LiDAR 장애물 회피와 연계
  └─ 도킹 시나리오 실증

Phase 4: 고도화 (선택)
  ├─ 다중 마커 맵 구축
  └─ DeepTag 도입 검토
```
